# Раздел 9. Frontend (React + TypeScript + Vite)

## 9.1. Принципы

| Принцип | Требование |
|---|---|
| Бизнес-правила | Источник истины — backend. UI не вычисляет допустимость переходов: кнопки действий строятся из `ticket.allowed_actions`; поля валидируются зеркально (zod), но итоговое решение принимает API |
| Mobile-first для инженера | Экраны инженера проектируются от ширины 360 px; остальные — адаптивно |
| Серверное состояние | TanStack Query: ключи по ресурсам, инвалидация после мутаций, `staleTime` 15 с для списков |
| Язык | Русский; строки в `src/i18n/ru.ts` (ключи), чтобы позже добавить `kk`/`en` |
| Без секретов в клиенте | Токены не хранятся в `localStorage`; сессия — HttpOnly cookie; CSRF-токен — в памяти |
| Время | Показ в часовом поясе площадки (по умолчанию `Asia/Almaty`) через `Intl.DateTimeFormat`; относительные подписи («2 ч назад») с точным временем в `title`/tooltip |

## 9.2. Структура проекта (frontend)

```
frontend/
  src/
    app/            # роутер, провайдеры (Query, Auth, Toast), layout
    api/            # клиент (fetch-обёртка: CSRF, Idempotency-Key, ошибки), типы из OpenAPI
    features/
      auth/ dashboard/ equipment/ tickets/ my-tasks/ report/ acts/
      notifications/ maintenance/ admin/ scan/
    components/     # UI-кит: Button, Input, Select, Modal, Toast, Badge, Table, Skeleton, EmptyState, FileUploader…
    styles/         # tokens.css (переменные), reset.css, global.css
    hooks/          # useOnlineStatus, useIdempotencyKey, useDebounce, usePolling
    i18n/ lib/ test/
```

Типы API генерируются из `openapi.json` (`openapi-typescript`, кандидат) на этапе сборки и коммитятся — контрактные расхождения ломают `tsc`.

## 9.5. Обязательные экраны

### 9.5.1. Вход

Поля: email, пароль (показать/скрыть), кнопка «Войти». Состояния: загрузка кнопки, ошибка «Неверный email или пароль» (без уточнений), блокировка «Вход временно заблокирован до HH:MM», `429`. Автозаполнение браузера разрешено (`autocomplete`).

### 9.5.2. Дашборд

* Сетка карточек KPI: «Активные», «Просроченные», «Ср. время реакции», «Ср. время до завершения», «Выполнено в срок», «Повторные неисправности».
* Блоки: заявки по статусам (столбчатая диаграмма с подписями и таблицей-альтернативой), загрузка инженеров (горизонтальные индикаторы + числа), список просроченных, ближайшие плановые даты.
* Клик по числу открывает список заявок выборки (`/analytics/metric-tickets`), чтобы цифру можно было проверить.
* Фильтры периода/организации/площадки. Пустое состояние: «Нет данных за выбранный период».
* Диаграммы — лёгкая библиотека (кандидат: `recharts` или собственные SVG); обязательна текстовая альтернатива для каждой диаграммы.

### 9.5.3. Реестр оборудования

Таблица/карточки: название, инвентарный №, тип, площадка, состояние, ближайшее ТО, активные заявки. Поиск (debounce 300 мс), фильтры, сортировка, пагинация. Действия A, D: «Добавить», «Печать этикеток» (выбор строк → PDF).

### 9.5.4. Цифровой паспорт

Шапка: название, статус состояния, инвентарный/серийный №, кнопки «Создать заявку» (C, D), «Открыть мою заявку» (E, если есть), QR (просмотр/печать/перевыпуск — A, D). Табы: **Обзор** (характеристики, площадка, ближайшее/последнее ТО, повторные неисправности), **История** (таймлайн заявок с диагнозом, работами, запчастями, ссылкой на актуальный акт), **Документы**, **План**.

### 9.5.5. Список заявок

Фильтры по 8.7 (чипы + панель), быстрые пресеты («Просроченные», «Мои», «Ожидают подтверждения»), индикатор SLA (остаток/просрочка: «ещё 3 ч 20 мин» / «просрочено на 1 ч 30 мин» или «часы остановлены»). Телефон: карточки со статусом и приоритетом.

### 9.5.6. Создание заявки

Шаги в одной форме: оборудование (поиск/выбор из своего списка; из QR — предзаполнено) → описание → срочность (три варианта с пояснением, для `emergency` — предупреждение «для угрозы жизни звоните …» (текст согласовать с компанией)) → контакт → фото (до 10 штук, прогресс по каждому). Перед отправкой: предупреждение о дубле, если есть `ACTIVE_TICKET_EXISTS` в предпросмотре (`GET /tickets?equipment_id=…&status=…`). Кнопка «Отправить» блокируется на время запроса; `Idempotency-Key` создаётся при открытии формы.

### 9.5.7. Карточка заявки с таймлайном

Левая часть: заголовок, статус, приоритет, SLA-индикатор, оборудование (ссылка на паспорт), исполнитель, описание, вложения (галерея + документы), запчасти, акты (версии, актуальный выделен), комментарии. Правая/нижняя часть: **таймлайн** (вертикальный: иконка, актор, время, описание, комментарий; internal-события помечены замком для сервисных ролей). Панель действий — кнопки из `allowed_actions`; каждое действие открывает модальное окно с нужными полями (см. 8.8) и подтверждением. Для сервисных ролей — вкладка «Назначения».

### 9.5.8. Мобильные задания инженера

Нижняя навигация; список карточек: номер, оборудование, площадка с адресом (ссылка на карту — внешняя, по клику), приоритет, SLA, плановое время визита, кнопка «Начать»/«Продолжить». Сверху — строка поиска/сканера QR. Pull-to-refresh и автообновление раз в 60 с. Группы сворачиваются.

### 9.5.9. Чек-лист и отчёт

Мастер из шагов с индикатором: **1. Диагностика → 2. Чек-лист → 3. Работы и результат → 4. Запчасти → 5. Фото → 6. Проверка и завершение**. Особенности:

* Чек-лист рисуется из `schema` (булевы переключатели «Норма/Не норма», числа с единицами и диапазоном, списки, комментарий при «не норма»).
* Автосохранение (индикатор «Сохранено 14:32» / «Сохранение…» / «Не сохранено — нет сети»).
* Фото: кнопка «Сделать фото» (`<input type="file" accept="image/*" capture="environment">`) и «Выбрать из галереи»; перед отправкой клиентское уменьшение до 2560 px по длинной стороне и JPEG качества ~0.85 (экономия трафика); выбор стадии «до/во время/после»; очередь загрузки с прогрессом, повтором и отменой.
* Шаг 6 вызывает `completion-check` и показывает список невыполненных условий со ссылками на шаги; кнопка «Завершить работы» активна, когда `ok=true`; до завершения — подтверждение в модальном окне («Будет сформирован акт версии N. Продолжить?»).
* Кнопка «Приостановить» всегда доступна (модальное окно 8.19.3).
* Запрос исключения по фото — ссылка на шаге 5.

### 9.5.10. Просмотр акта

Встроенный просмотр PDF (`<iframe>`/`<object>` с запасной кнопкой «Скачать»), панель: версия, статус (**«Актуален» / «Неактуален — возвращён клиентом» / «Подтверждён»**), метаданные подтверждения. Для клиента при актуальной версии — «Подтвердить результат» (с оценкой и комментарием) и «Вернуть на доработку» (комментарий обязателен). Текст рядом с кнопкой: «Подтверждение в системе фиксирует ваше решение и не является электронной подписью».

### 9.5.11. Уведомления

Список с группировкой «Сегодня/Ранее», индикатор непрочитанных в шапке (опрос 30 с, пауза на скрытой вкладке), «Отметить все прочитанными», переход по ссылке на заявку (если доступна). Пустое состояние: «Уведомлений нет».

### 9.5.12. Пользователи и справочники

Таблицы с поиском и фильтрами; формы создания/редактирования; диалог «Временный пароль» (показывается один раз, кнопка «Копировать», предупреждение «Передайте пароль безопасным способом; после закрытия окна он не будет показан»); деактивация с перечнем блокирующих активных заявок. Шаблоны чек-листов — редактор пунктов (черновик) + предпросмотр + «Опубликовать» с подтверждением.

## 9.6. Состояния интерфейса

| Состояние | Поведение |
|---|---|
| Загрузка | Скелетоны, повторяющие разметку (не спиннер на весь экран); кнопки с индикатором и блокировкой повторного нажатия; для запросов > 10 с — подсказка «Это занимает дольше обычного» |
| Пусто | Иллюстрация-иконка, текст «что это» и «что сделать» + кнопка (пример: «У вас пока нет заданий — когда диспетчер назначит заявку, она появится здесь») |
| Ошибка запроса | Блок с сообщением из `error.message`, кнопка «Повторить», `request_id` мелким шрифтом для обращения в поддержку |
| Ошибка валидации | Сообщения у полей (`aria-describedby`), фокус на первом ошибочном поле, сводка сверху на длинных формах |
| `401` | Сохранить `next`, перенаправить на `/login` с сообщением «Сессия завершена» |
| `403` / `404` | Страницы с понятным текстом и ссылкой «На главную» (для `404` по QR — поле ручного поиска) |
| `409 VERSION_CONFLICT` | Баннер «Заявка изменена пользователем …, данные обновлены. Проверьте и повторите действие»; данные перезагружаются, введённые поля формы сохраняются |
| `409 INVALID_TRANSITION` | То же, с актуальным статусом |
| `422 COMPLETION_REQUIREMENTS_NOT_MET` | Список условий с переходами к шагам |
| `5xx` | Toast «Не удалось выполнить действие. Повторите. Код: …» |

**Подтверждения действий** (модальные окна с фокус-ловушкой, `Esc` закрывает, фокус по умолчанию на безопасной кнопке): отклонить, отменить, завершить, подтвердить акт, вернуть на доработку, деактивировать пользователя, перевыпустить QR, опубликовать шаблон, архивировать. Для действий с комментарием поле обязательно с счётчиком символов.

**Прогресс загрузки файлов:** индикатор по каждому файлу (XHR/`fetch` с потоковым прогрессом через `XMLHttpRequest.upload`), общая сводка «3 из 5», кнопки «Повторить»/«Отмена», превью (миниатюра до загрузки — `URL.createObjectURL`). Файл, не прошедший проверку (тип/размер), помечается до отправки по правилам 6.9.

## 9.7. Поведение при потере соединения

| Сценарий | Поведение |
|---|---|
| Потеря сети (`navigator.onLine`, неудачный `fetch`) | Постоянный баннер «Нет соединения. Показаны сохранённые данные; действия временно недоступны». Кнопки мутаций (кроме сохранения черновика отчёта) блокируются с пояснением |
| Черновик отчёта | Поля сохраняются локально (IndexedDB, ключ `ticket_id + revision`, зашифрованность не требуется: данные не содержат секретов, очистка при выходе пользователя). После восстановления сети отправляются с актуальным `version`; при конфликте — экран сравнения «Моя версия / Версия на сервере» |
| Загрузка фото | Неудачные загрузки остаются в очереди со статусом «Ожидает сети»; повтор вручную или автоматически при `online`, с тем же `Idempotency-Key` |
| Переходы статусов | Офлайн **не выполняются** (нужна проверка актуальности на сервере); при обрыве во время запроса UI показывает «Результат неизвестен — проверяем…», повторяет `GET /tickets/{id}`; если статус изменился — отображает результат, иначе предлагает повторить (тот же `Idempotency-Key`) |
| Возврат сети | Баннер «Соединение восстановлено», рефетч активных запросов |
| Полный офлайн-режим (PWA) | **Вне MVP**; зафиксирован в развитии |

## 9.8. QR и камера

* **Основной путь:** штатная камера телефона читает QR (URL) и открывает `https://…/e/{code}`. Работает без разрешений браузера на камеру.
* **Встроенный сканер** `/scan`: используется `getUserMedia`, который доступен **только в защищённом контексте** (HTTPS или `localhost`). При `http://IP` страница показывает объяснение и ручной ввод. Для пилота на локальном сервере требуется сертификат, которому доверяют устройства: публичный домен + Let's Encrypt либо корпоративный/локальный CA (раздел 11.10).
* Запрос разрешения камеры — после нажатия «Включить камеру» (не при загрузке); отказ → инструкция по включению и ручной поиск.
* Ручной поиск: поле принимает инвентарный номер, серийный номер, код QR (12 символов), номер заявки `SR-…`; результаты — через `/search` и `/equipment/by-qr/{code}`.
* После распознавания — вибро-отклик (`navigator.vibrate`, если доступен), переход в паспорт.

## 9.9. Анимации и доступность

| Тема | Требование |
|---|---|
| Длительность | 120–200 мс, easing `ease-out`; допустимы: появление/скрытие модальных окон и дроверов (opacity + translateY ≤ 8 px), раскрытие аккордеонов, плавное появление toast, прогресс-бары |
| `prefers-reduced-motion: reduce` | Отключаются все transform-анимации, shimmer скелетонов заменяется статичным фоном, плавный скролл → мгновенный; смена состояний — без движения (допускается мгновенная смена или `opacity` ≤ 100 мс) |
| Клавиатура | Все действия доступны с клавиатуры; видимый фокус (контур 2 px, контраст ≥ 3:1); порядок табуляции логичен; `Esc` для модальных окон |
| Семантика | Правильные `h1–h3`, `main/nav/header`, `button`/`a` по назначению, `aria-live` для уведомлений об ошибках и сохранении, `aria-busy` у загружаемых блоков |
| Контраст | Текст ≥ 4.5:1, крупный текст и элементы интерфейса ≥ 3:1; проверка axe в E2E-10 |
| Формы | Видимые `label`, подсказки, ошибки рядом с полем; `inputmode`/`autocomplete` для телефона и email |
| Таблицы | `<th scope>`; на телефоне — карточки с теми же данными |
| Языковые атрибуты | `<html lang="ru">` |

# Раздел 13. Тестирование и приёмка

## 13.1. Стратегия

| Уровень | Инструменты | Что проверяет | Когда запускается |
|---|---|---|---|
| Unit (UT) | pytest; Vitest + RTL | Чистая логика без БД и сети: state-machine, `SlaClock`, валидаторы, политика видимости, формулы | при каждом коммите (CI) |
| Integration (IT) | pytest + HTTPX на реальном PostgreSQL (контейнер `db-test`) | API целиком: права, транзакции, идемпотентность, БД-ограничения, seed, миграции, аналитика | каждый PR (CI) |
| E2E | Playwright (`desktop-chromium`, `mobile-chromium`) на стенде с demo-данными и часами `fixed = T0` | Сквозные сценарии пользователей | PR в `main` и ночной прогон |
| Нагрузочные (LT) | Locust (кандидат) или k6 | Время ответа и устойчивость при целевой нагрузке | перед пилотом, после крупных изменений БД |
| Эксплуатационные (OP) | Скрипты + ручные проверки по чек-листу | Запуск, перезапуск, backup/restore, обновление, сеть, HTTPS | перед пилотом и после изменений инфраструктуры |

**Данные:** все IT/E2E используют demo-набор раздела 12 (фикстура `demo_db`), а для проверки отдельных правил создают минимальные записи фабриками. Часы — `fixed` на `T0 = 2026-03-16T10:00:00Z`, перевод времени — фикстурой `clock.set(...)`.

**Правила тестов:** независимость (тест не зависит от порядка), проверка и ответа API, и состояния БД, и записей `ticket_events`/`audit_log`; негативные тесты обязательны для каждого правила доступа.

Обозначения ролей в шагах: **CL1/CL2/CL3** — клиенты `U-CL1/2/3`, **DSP** — диспетчер, **ENG1/ENG2** — инженеры, **MGR** — руководитель, **ADM** — администратор. Номера заявок сокращены (`0013` = `SR-2026-0013`).

# Alageum Service Hub (MVP)

Веб-платформа учёта электротехнического оборудования и сервисного обслуживания: клиент → диспетчер → инженер → руководитель.
Проект предлагается студенческой командой Университета имени М. Әуезова для **возможного** пилота; сотрудничество с компанией **не подтверждено**, все данные — синтетические.

Стек: FastAPI + SQLAlchemy/Alembic + PostgreSQL · React + TypeScript + Vite · Nginx · Docker Compose · pytest/HTTPX · Vitest · Playwright.
Полное ТЗ — в [docs/](docs/README.md); что реализовано и чем отличается от ТЗ — [docs/12-implementation-status.md](docs/12-implementation-status.md).

## Запуск (demo)

Нужны Docker и Docker Compose.

```bash
./scripts/gen-secrets.sh                 # создаёт .env и случайные секреты
docker compose build
docker compose up -d --wait              # db → migrate → api → worker → web
docker compose --profile demo run --rm seed   # demo-данные (только APP_ENV=demo/dev/test)
```

Откройте http://localhost:8100. Пароль всех demo-пользователей — значение `DEMO_USER_PASSWORD` из `.env`.

| Роль | Email |
|---|---|
| Администратор | admin@demo.alageum.test |
| Диспетчер | dispatcher@demo.alageum.test |
| Руководитель | manager@demo.alageum.test |
| Инженеры | engineer1@demo.alageum.test, engineer2@demo.alageum.test |
| Клиенты | client.metal@…, client.agro@…, client.logistics@… (`@demo.alageum.test`) |

Главный экран работы с заявками — **доска** (`/board`): канбан, список, календарь, шкала SLA, обновление в реальном времени.

Demo-время зафиксировано: `2026-03-16T10:00:00Z` (`APP_CLOCK_MODE=fixed`), на нём дашборд совпадает с ожидаемыми значениями ТЗ (раздел 12.6).
## Доступ с телефона и других устройств (локальная сеть)

- **Адреса:** `http://<IP_компьютера>:8100` (обычный) и `https://<IP_компьютера>:8443` (защищённый). IP компьютера: `ipconfig` → «IPv4-адрес» Wi-Fi.
- **Камера сканера и геолокация** работают в браузере только по HTTPS (или на localhost). На http-странице сверху показывается подсказка со ссылкой «Открыть защищённую версию». При первом входе по HTTPS браузер предупредит о самоподписанном сертификате — «Дополнительно» → «Продолжить».
- **Сертификат:** `bash scripts/make_cert.sh <IP1> [<IP2>...]` создаёт `certs/server.crt` и `certs/server.key` (в git не попадают); затем `docker compose restart web`. Если IP компьютера сменился (DHCP), выпустите сертификат заново.
- **QR-коды:** в `.env` задано `APP_PUBLIC_URL=auto` — ссылка в QR строится по адресу, с которого открыт сайт, поэтому смена IP не ломает новые QR. Для постоянного домена укажите его явно: `APP_PUBLIC_URL=https://service.example.kz`.
- **Брандмауэр Windows** (PowerShell от администратора):
  `New-NetFirewallRule -DisplayName "Alageum" -Direction Inbound -Protocol TCP -LocalPort 8100,8443 -Action Allow -Profile Any`
- Если после пересоздания `api` сайт отвечает 502 — `docker compose restart web`.

## Пароли пользователей (администратор)

Администратор может назначить каждому пользователю **свой пароль**: при создании («Пароль» в форме) и позже — кнопка-ключ «Задать пароль» в строке пользователя или поле «Новый пароль» в форме изменения. Есть генератор (14 символов), показ/копирование и флажок «Потребовать смену пароля при первом входе» (по умолчанию выключен). Минимум 12 символов, простые пароли отклоняются. После назначения прежние сеансы пользователя завершаются, а пароль нигде не сохраняется и не попадает в журнал аудита. Если пароль не задан — по-прежнему создаётся временный (показывается один раз), а кнопка «Сбросить пароль» выдаёт новый временный. API: `POST /api/v1/users/{id}/set-password`.

## Сеанс входа

Сеанс длится **10 минут без действий**: любое обращение к серверу или действие пользователя продлевает его, а пока вы работаете (читаете, заполняете форму), браузер сам продлевает сеанс. За минуту до выхода показывается предупреждение «Сеанс завершится через N с» с кнопкой «Продолжить работу»; после истечения — страница входа с пояснением, после входа ещё 10 минут. Настройки: `SESSION_IDLE_TTL_MINUTES` (по умолчанию 10) и `SESSION_ABS_TTL_MINUTES` (предел сеанса, 480 = 8 часов; чтобы требовать вход строго через 10 минут, задайте здесь 10). Время сеанса считается по настоящим часам, даже когда часы demo заморожены. Команда `seed-demo --force` сохраняет действующие входы, поэтому пересев демо-данных больше не «выкидывает» из системы.

## Дизайн-система

Вся палитра, радиусы, тени и скорости анимаций заданы токенами в `frontend/src/styles/tokens.css` (фиолетовая гамма, градиенты шапки и боковой панели); компоненты и анимации — `frontend/src/styles/theme.css`. Каркас: фиолетовая шапка с поиском, уведомлениями и профилем, боковая панель с индикатором активного раздела (на планшете — узкая панель значков, на телефоне — нижняя навигация и меню «Ещё»), мягкие белые карточки, таблицы со значками действий и «таблетками» статусов, анимированная страница входа. Все анимации отключаются при настройке системы «уменьшить движение». Фотографии за боковой панелью (`frontend/public/bg/`) плавно сменяются каждые 30 секунд, кнопка внизу панели меняет их вручную (выбор запоминается). Навигация по устройствам: на компьютере боковая панель сворачивается кнопкой в шапке до значков (выбор запоминается); на планшете слева узкая панель только из значков, кнопка раскрывает полное меню поверх страницы; на телефоне шапки нет — всё внизу, как панель задач (разделы, а в меню «Ещё» — поиск, уведомления, профиль и выход). Страница входа — строгая синяя.

## Дашборд и визуализация

Показатели руководителя — карточки со значком, «набегающим» числом и мини-визуализацией (полукруглые датчики для процентов, цветная полоска приоритетов), объёмная **3D-круговая диаграмма статусов** (секторы выезжают при появлении, при наведении выдвигаются, нажатие открывает список заявок), **изометрические 3D-колонки** (активные заявки по приоритетам, загрузка инженеров с «тенью» вместимости) и сводка сигналов «авария / вызов / плановые» со ссылкой на карту. Всё нарисовано на SVG без внешних библиотек (`frontend/src/components/charts/`); при включённом в системе «уменьшении движения» диаграммы сразу показывают итог; значения дублируются текстом (легенда, скрытые списки) для экранных дикторов.

## Карта и геолокация (OpenStreetMap)

- **Положение оборудования:** у оборудования есть собственные `latitude`/`longitude` (оси координат); если не заданы — используется положение площадки. Редактор: паспорт оборудования → вкладка «Карта» → «Изменить положение» (диспетчер, администратор) — широта и долгота вручную, щелчок по карте, перетаскивание синей метки или «Моё местоположение». Те же поля есть в форме оборудования. Координаты площадки: «Организации и площадки» → «Координаты».
- **Карта объектов** (раздел «Карта», API `GET /api/v1/map/objects`): значки типов — трансформатор (две катушки), подстанция КТП (здание с молнией), РУ — распределительная подстанция (строение с шинами); цвет и сигнал состояния — **авария** (красный, мигает: критическая заявка или оборудование выведено из работы), **вызов** (оранжевый: аварийная/корректирующая заявка в работе), плановые работы (синий), в норме (зелёный). Фильтры по сигналам и типам, список сигналов, подлёт к метке, маршрут и расстояние от вас. Обновляется в реальном времени (SSE).
- **Плитки карты** идут через наш nginx (`/tiles/{z}/{x}/{y}.png`) с кэшем 60 дней (volume `tiles`) и User-Agent приложения — так OpenStreetMap не блокирует запросы (раньше браузер получал «403 Access blocked»), а карта переживает кратковременные сбои сети. Серверу нужен выход в интернет и DNS; свои DNS-серверы: `TILE_DNS="10.0.0.1 10.0.0.2"` в `.env` (по умолчанию `1.1.1.1 8.8.8.8 127.0.0.11`). Для интенсивной эксплуатации используйте собственный тайл-сервер (политика OSM: https://operations.osmfoundation.org/policies/tiles/).
- **Тачпад (ноутбук).** Кнопка «Тачпад» под картой включает управление двумя пальцами: прокрутка перемещает карту (страница при этом не прокручивается), щипок (или Ctrl+колесо) масштабирует вокруг указателя; выбор запоминается. Щипок всегда масштабирует карту, а не страницу. Работают также стрелки и +/− при фокусе на карте, двойной щелчок и жесты на сенсорном экране.
- **Демо-данные** привязаны к Шымкенту (центр карты по умолчанию — 42.3417, 69.5901). Тип «РУ» — распределительная подстанция.
- Положение пользователя не сохраняется и на сервер не отправляется; геолокация работает только по HTTPS.

QR-коды demo: `http://localhost:8100/e/DEMOEQUIP001` … `DEMOEQUIP010`.

## Команды

```bash
docker compose logs -f --tail=200 api worker web      # логи
docker compose stop                                   # остановка без удаления данных (docker compose down тоже сохраняет тома)
./scripts/backup.sh                                   # backup → backups/<UTC-метка>/
./scripts/restore.sh backups/<метка>                  # восстановление
docker compose run --rm api python -m app.cli create-admin --email admin@example.org   # администратор (пароль запрашивается)
docker compose run --rm api python -m app.cli verify-storage                           # сверка файлов и БД
docker compose --profile demo run --rm seed python -m app.cli seed-demo --force        # пересоздать demo (стирает ВСЕ данные БД)
```

## Разработка

`docker compose -f compose.yaml -f compose.dev.yaml up -d` — исходники backend монтируются, API на `127.0.0.1:8000`, БД на `127.0.0.1:5432`.
Frontend: `cd frontend && npm ci && npm run dev` (прокси на `http://localhost:8000`).
Версии зафиксированы: Python — `backend/requirements.lock`, JS — `frontend/package-lock.json` (точные версии, `save-exact`).
